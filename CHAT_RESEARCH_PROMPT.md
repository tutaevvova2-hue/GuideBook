# Промпт для чата Claude: исследование мода (досье для Gemini)

Схема: Claude в чате ищет и читает источники и выдаёт досье по главам. Вы сохраняете каждое досье в репозиторий как `books/<книга>/sources/research/chN.md`. Gemini пишет главу по досье, цифры сверяет с `stats.md`/`mobs.json` (задание `ГЛАВА N`, шаг 0 проверяет наличие досье).

Как пользоваться:
1. Создайте в Claude **Проект** и загрузите в него как постоянные файлы: `REQUIREMENTS.md`, `books/FORMAT.md`, `books/divine/PLAN.md` (образец плана) и, если есть, `PLAN.md` нужной книги. Тогда правила не надо вставлять каждый раз.
2. Один мод = один чат (или два, если мод большой). Чат начинайте с блока ниже, подставив название мода.
3. К сообщению приложите файл данных мода из репозитория: `tools/data/mod_<modid>.json` (или его выжимку), чтобы Claude знал точный список предметов и русских названий.
4. Модель: **Sonnet** для досье, **Opus** только для плана книги на первом шаге.

---

## Блок 1. План книги (Opus, один раз на мод)

Ты помогаешь готовить книгу-справочник по моду **<МОД>** для Minecraft 1.12.2. Правила книг в приложенных `REQUIREMENTS.md` и `FORMAT.md`; образец плана — `PLAN.md` по DivineRPG.

**Критерий полноты.** Эталон — самодостаточность: игрок с одной книгой в руках понимает весь мод и ни разу не лезет в интернет. Каждая возможность мода (предмет, блок, механика, постройка, интерфейс, режим, ограничение, типичная ошибка) должна быть объяснена там, где игрок её встретит, и настолько, чтобы ею можно было пользоваться. Объём определяется числом возможностей мода, а не желаемым размером книги.

Задача: найди в интернете (английские и русские источники: официальная вики мода, страница мода на CurseForge и репозиторий, руководства, обсуждения) полный перечень возможностей мода и составь два файла:
1. `PLAN.md` в формате плана из образца: таблица «№ / Глава / Что внутри / Открывается», «Правила для глав», «Источники». Порядок глав — порядок знакомства игрока с модом.
2. `COVERAGE.md`: таблица «возможность мода → глава → статья». Пустых строк быть не должно; если возможность не нужна игроку, пиши это и причину.

Сверяй перечень с приложенным файлом данных: каждый предмет из него должен попасть в какую-то главу. Отдельно перечисли предметы из данных, для которых не нашёл описания. Отдай оба файла в виде блоков кода, без вступлений и пересказа.

## Блок 2. Досье по главе (Sonnet, по одной главе за сообщение)

Составь досье к главе **N «<название>»** книги по моду **<МОД>** (Minecraft 1.12.2) по приложенному `PLAN.md`. Досье станет единственным источником для более слабой модели, которая будет писать текст главы; сама она в интернет не ходит, поэтому в досье должно быть всё нужное, полно и точно.

**Иди по темам главы (каждый предмет, существо, блок, механика из строки главы в плане) и для каждой найди источники:**
- вики мода и другие руководства;
- форумы (Minecraft Forum, Reddit, обсуждения на CurseForge и GitHub-issues мода);
- гайды и разборы (в том числе транскрипты и описания видео, если текст удаётся прочитать);
- по-английски и по-русски. Англоязычный интернет обычно полнее, ищи там в первую очередь.
Минимум 3–5 разных источников на тему, где они есть. Не ограничивайся первой страницей выдачи.

**Формат досье** (markdown, ровно такие разделы, для каждой темы):

```
# Досье: глава N «<название>» — <МОД>

## <Тема / предмет / механика>
Название в игре (англ. / рус. из перевода, если известно): …
**Факты**
- <факт> [ссылка] (достоверность: 1 = подтверждено кодом или данными, 2 = вики/руководство, 3 = форум/видео)
**Как получить / создать**: …
**Как работает и как пользоваться**: …
**Числа, как их называют источники** (урон, прочность, время, ёмкость, скорость): … — пометка «сверить с кодом», если источник про другую версию мода
**Советы игроков**: …, (сколько источников это подтверждают)
**Типичные ошибки и подводные камни**: …
**Что откроется дальше / с чем связано**: …
**Расхождения между источниками**: …
**Не нашёл**: …

… (следующая тема) …

## Ссылки
Использованные: …
Не открылись или недоступны: …
```

**Правила.**
- Ничего не выдумывай и не пересказывай по памяти. Нет сведений — пиши «не нашёл». Числа приводи только вместе со ссылкой и версией мода, на которую она относится; расхождения между версиями отмечай.
- Различай проверенное (уровни 1–2) и слухи (уровень 3). Совет с форума без подтверждения второго источника помечай «один источник».
- Не пиши текст главы, только материал: факты, механика, советы.
- Формулировки нейтральные и подробные, но без воды. Никаких оценок вроде «отличный мод».
- Если тем слишком много для одного ответа, остановись на середине списка и напиши «продолжение: тема X»; на «дальше» продолжай с того места, не повторяя сделанное.
- Отдай результат одним блоком markdown, готовым к сохранению в `books/<книга>/sources/research/chN.md`.

## Блок 3. Проверка досье (Sonnet, короткое сообщение, по желанию)

Перечитай собственное досье и приложенный список предметов главы. Найди: (1) предметы и механики главы, которых в досье нет; (2) числа без ссылок; (3) советы без указанного числа подтверждений. Допиши недостающее теми же правилами и выдай только дополнения.

---

## Как сохранить и передать Gemini
1. Скопируйте досье в файл `books/<книга>/sources/research/chN.md` (в Codespaces: создать файл, вставить, сохранить).
2. `git add -A && git commit -m "Досье главы N" && git push`.
3. В `gemini`: `Выполни задание ГЛАВА N`. Шаг 0 увидит досье и не станет искать в интернете сам.
4. Проверка `python tools/lint_book.py <книга>` предупредит, если досье нет или в нём меньше трёх ссылок.
