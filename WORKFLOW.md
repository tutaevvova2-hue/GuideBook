# Рабочие задания (единый источник)

Пользователь даёт короткую команду вида: **«Выполни задание <ИМЯ> [для главы N / мода X]»**.
Действуй строго по описанию задания ниже. Формулировки здесь не переписывай и не сокращай. Если задание не подходит, спроси, а не импровизируй.

Общие правила для всех заданий:
- Сначала прочитай `GEMINI.md`, `REQUIREMENTS.md`, `books/FORMAT.md` и `books/<книга>/HANDOFF.md`.
- Цифры и рецепты бери только из файлов данных. Нет факта — не выдумывай, а запиши в раздел «Не хватило данных» в конце ответа и в `HANDOFF.md`.
- Не трогай `tools/`, `vendor/`, `build.py`, `books/industrial/`, если об этом прямо не просили.
- В конце любого задания по порядку: `python build.py --check` до `OK`; `python tools/lint_book.py <книга>` до `LINT OK` (ошибки исправляй, предупреждения о `== shot`, «Что дальше» и неупомянутых предметах тоже устраняй, кроме предметов, которые относятся к другим главам по `PLAN.md`); обновить `HANDOFF.md` (что готово, проверенные факты, чего не хватило); `git add -A`; `git commit`; `git push`.
- Прохождение `build.py --check` не означает, что глава хороша. Перед коммитом сравни текст с `PLAN.md`: все ли пункты главы раскрыты, у каждого главного предмета есть цифры из `stats.md`, у каждой статьи есть совет и «Что дальше».
- Если чего-то не хватает в данных, запиши это в `HANDOFF.md` в раздел «Не хватило данных» и не выдумывай.

## ЗАДАНИЕ ГЛАВА (глава N)
1. Прочитай строку главы N в `books/<книга>/PLAN.md` и образец `01_ores.txt`.
2. Напиши `books/<книга>/NN_<раздел>.txt`, где `NN` — следующий номер по порядку.
3. В каждой статье: spotlight главного предмета, цифры, рецепт (`== craft`), как пользоваться, практический совет, страница «Что дальше», строка `unlock: <группа>`.
3а. Цифры: для главного предмета (`== spotlight`), который есть в `sources/stats.md`, в тексте статьи должны стоять его урон и прочность (или «не ломается»); для брони — защита набора. Для существ бери здоровье, урон и выпадение из `sources/mobs.json`. Не пиши «тяжёлый удар» вместо числа.
4. **Скриншоты обязательны.** В каждой статье с нечитаемым по тексту содержанием (внешний вид постройки, существа, окно машины, портал, бой с боссом) поставь минимум одну страницу `== shot <имя>.png | <заголовок>` по формату из `books/FORMAT.md`: описание, что именно снять, строка `--`, подпись. Имена файлов: латиница, строчные, `<статья>_<что>.png`, без пробелов. Не ставь `== shot`, если картинка не нужна.
5. Новые группы открытия допиши в `books/<книга>/unlocks.txt`.
6. Запусти `python build.py`: он сам обновит `SCREENSHOTS.md`. Открой этот файл и убедись, что все новые кадры там есть.
7. Общие правила (проверка, `HANDOFF.md`, коммит, пуш).

## ЗАДАНИЕ СКРИНЫ (глава N или «все»)
Цель: список кадров для главы. Ничего в тексте глав не переписывай, кроме добавления недостающих `== shot`.
1. Пройди по статьям главы N (или всех глав книги).
2. Для каждой статьи, где картинка нужна, но `== shot` нет, добавь его по правилам из шага 4 задания ГЛАВА.
3. Запусти `python build.py`, затем прочитай `SCREENSHOTS.md`.
4. Выведи мне готовый список: имя файла, статья, что снять, настройки кадра (F1 да/нет, время суток, место). Сверь с `SCREENSHOTS.md`.
5. Общие правила.

## ЗАДАНИЕ ПЛАН (мод X)
1. Проверь, что в `tools/data/mod_<X>.json` и `books/<X>/sources/` есть данные. Если нет, скажи, чего не хватает, и остановись.
2. Прочитай `books/divine/PLAN.md` как образец формата.
3. Составь `books/<X>/PLAN.md`: таблица «№ / Глава / Что внутри / Открывается», правила для глав, источники. Порядок глав — порядок прохождения по руководству.
4. Создай `books/<X>/HANDOFF.md` по образцу `books/divine/HANDOFF.md` (порядок работы, что готово, проверенные факты).
5. Общие правила.

## ЗАДАНИЕ ДАННЫЕ (мод X)
Пользователь заранее положил jar мода в папку `mods/` (в Codespaces: перетащить файл в панель файлов слева). Если файла нет, скажи об этом и остановись.
1. `python tools/moddata.py mods/<X>.jar <modid>` — названия и рецепты в `tools/data/mod_<modid>.json`.
2. `python tools/decompile.py mods/<X>.jar` — читаемый код в `build/src/<X>/` (несколько минут).
3. Найди в коде числа и выпиши в `books/<X>/sources/stats.md` (таблицы в формате `books/divine/sources/stats.md`: оружие, инструменты, броня) и `mobs.json` (здоровье, урон, выпадение, по образцу divine). Искать через `grep -rn` по `build/src/<X>/`: классы предметов, `ToolMaterial`, `ArmorMaterial`, `setMaxDamage`, `getMaxHealth`/`SharedMonsterAttributes`, таблицы лута (`dropItem`, `LootTable`). Не угадывай: значение берётся только из кода. Не нашёл — в список «Не хватило данных».
4. Скачай руководство или вики мода в `books/<X>/sources/`, если пользователь дал ссылку.
5. Общие правила.

## ЗАДАНИЕ СБОРКА
1. `python build.py` (проверка и сборка).
2. Скажи пользователю точный путь `dist/Tomes-1.12.2-<версия>.jar` и напомни: скачать файл сразу (правый клик в панели файлов → Download), `dist/` не хранится в git.
3. `git push`, если есть незапушенные коммиты.

## ЗАДАНИЕ ПРОВЕРКА (глава N)
Запусти `python tools/lint_book.py <книга>`. Прочитай главу N и сверь с `REQUIREMENTS.md` и файлами данных: запрещённые слова (мод, сборка, версия, конфиг), «ты», названия предметов, цифры, полноту по `PLAN.md`. Исправь найденное, покажи список правок. Общие правила.

## ЗАДАНИЕ ПРАВКА (текст замечания от пользователя)
Исправь только то, что описано в замечании. Остальное не трогай. Общие правила.
