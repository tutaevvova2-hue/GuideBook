# Промпт для нового чата с Claude (сбор данных и план по одному моду)

Использовать: открыть новую сессию Claude Code на этом репозитории, ветка `claude/happy-brown-u5fbmc`, модель Sonnet. Скопировать блок ниже, подставив название мода вместо `<МОД>` (Mystcraft / Railcraft / Steve's Carts 2). Jar мода приложить к первому сообщению файлом (как вы прикладывали `GuideBook.rar`); Claude сам положит его в `mods/` (папка не попадает в git).

---

Ты готовишь данные и план книги-справочника для мода **<МОД>** (Minecraft 1.12.2). Главы будет писать другая, более слабая бесплатная модель, поэтому от тебя нужен результат в файлах: полный, точный и удобный для чтения. Сам текст глав не пиши.

**Бюджет.** У меня очень мало платных токенов. Работай экономно: не читай подряд целые страницы и файлы, сначала ищи `grep`-ом и читай только нужные куски; ничего не пересказывай мне повторно. После каждого этапа пиши одну строку «этап N готов, потрачено примерно X токенов». Если к концу этапа 3 набралось больше половины разумного объёма, остановись и спроси меня, продолжать ли.

**Что прочитать сначала (только это):** `REQUIREMENTS.md` (правила П-1…П-39, особенно П-6 про погружение и П-20 про «Что дальше»), `books/FORMAT.md`, `WORKFLOW.md` (задания ДАННЫЕ и ПЛАН, иерархия достоверности), `books/divine/PLAN.md` и `books/divine/HANDOFF.md` как образец формата плана и передаточного файла. Эталон объёма: IC2 (`books/industrial/`: 17 разделов, 158 статей) и MFFS по глубине проработки. Объём книги по <МОД> определяется его реальными возможностями: не раздувай и не сокращай, каждую механику, предмет и постройку мода нужно учесть.

**Этапы (делай по порядку):**

1. **Данные.** Положи приложенный jar в `mods/`. `python tools/moddata.py mods/<jar> <modid>` → `tools/data/mod_<modid>.json`. Проверь, что русские названия (`ru_ru.lang`) и рецепты выгрузились. Если у мода нет русского перевода, отметь это.
2. **Код.** `python tools/decompile.py mods/<jar>`. Выпиши из кода числа и правила в `books/<книга>/sources/`: `stats.md` (предметы, инструменты, двигатели, ёмкости, скорости, стоимость), `mobs.json` (если у мода есть существа), а для механик мода (конструкции, GUI, сигналы, энергия, топливо и т. п.) заведи `mechanics.md`: как это работает по коду, с числами и условиями. Значения только из кода, без угадывания. Не нашёл — в список «Не хватило данных».
3. **Вики.** Найди основную вики или руководство мода. Проверь, что скрипт `tools/research.py wikisearch <хост> "<запрос>"` его читает; хосты, которые закрыты для скрипта, читай встроенным инструментом и сохраняй командой `research.py paste`. Сохрани в `books/<книга>/sources/research/raw/` страницы по каждой крупной теме (не более 40 страниц; выбирай по оглавлению, а не подряд). Форумы, Reddit и видео не читай, кроме случая, когда механику невозможно понять иначе.
4. **План.** Составь `books/<книга>/PLAN.md` по образцу `books/divine/PLAN.md`: таблица «№ / Глава / Что внутри / Открывается», правила для глав, источники. Порядок глав — порядок знакомства игрока с модом. Если мод по П-2 делится на части, размести части как главы одной книги. Для каждой главы перечисли предметы и механики, которые обязаны быть раскрыты (список по данным, а не по памяти). Отдельно отметь, какие главы нуждаются в скриншотах.
5. **Передаточный файл.** Создай `books/<книга>/HANDOFF.md` по образцу divine: порядок работы над главой, источники и хосты вики (какие открываются скриптом, какие нет), проверенные факты из кода, раздел «Не хватило данных». Создай пустые `unlocks.txt` и `book.json` по образцу divine с названием, которое вписывается в мир (П-6).
6. **Проверка и пуш.** `python build.py --check` и `python tools/lint_book.py <книга>`. Затем `git add -A`, `git commit`, `git push` в текущую ветку. Список того, что осталось неясным, выведи мне коротко, в конце.

**Правила.**
- Иерархия достоверности из `WORKFLOW.md`: числа и рецепты только из кода и данных; вики только для порядка прохождения и описаний.
- Обновить `GEMINI.md`: строка «Текущая книга» должна указывать на новую книгу и мод.
- Не меняй `tools/`, `vendor/`, `build.py` и чужие книги, кроме случая, когда без этого нельзя; тогда объясни причину.
- Не придумывай факты. Не пиши текст глав.

Результат: `PLAN.md`, `HANDOFF.md`, `sources/*`, `unlocks.txt`, `book.json`, коммит в ветке. После этого главы будут писаться заданием «ИССЛЕДОВАНИЕ» и «ГЛАВА» в Gemini CLI.
